# 「我的输入源」设计与 Luna 执行说明

> 状态：框架已确定，待实现。  
> 范围：仅新增「关于我 → 我的输入源」子页，不改现有首页、运营、影像作品和联系方式。  
> 目标：让求职者在看到经历与作品之外，进一步感知邱孝淼的审美来源、生命力和「活人感」。

## 1. 核心决策

- 对外名称：**我的输入源**
- 英文辅助文字：`PERSONAL INPUTS`
- 入口位置：现有「关于我」页面内，技能标签与学校信息附近
- 入口文案：`进入我的输入源  ↘`
- 打开形式：全屏子页 / 对话层，不在原「关于我」画面里硬塞封面
- 内部导航：`音乐 / 电影 / 训练`
- 默认打开：`音乐`
- 不把这一部分命名为「兴趣爱好」

### 为什么采用子页

现有「关于我」已经承担个人介绍、技能、校园经历和实习经历。音乐、电影和训练再直接铺开，会破坏首屏层级。子页能让它保持个人感，同时不抢走求职主线。

## 2. 信息架构

```text
关于我
└─ 进入我的输入源
   ├─ 音乐 MUSIC
   │  ├─ 长期喜欢的歌手
   │  └─ 反复听的专辑
   ├─ 电影 FILMS
   │  └─ 海报 + 私人感想
   └─ 训练 TRAINING
      └─ 本人健身照片 + 可选的短句/训练记录
```

## 3. 桌面端线框

### 3.1 「关于我」入口

```text
我用影像理解内容，
也用数据验证表达。

[摄影]  [内容运营]  [AI 工具]

进入我的输入源  ↘
闽南师范大学 · 2027
```

入口是细边框矩形文字按钮，不使用胶囊，不放额外图标。悬停时反转为白底黑字，与现有导航交互一致。

### 3.2 全屏子页通用结构

```text
┌─邱孝淼 / 淼淼─────────────────────────────────────┐
│                                                        [×] │
│  我的输入源                            音乐  电影  训练 │
│  PERSONAL INPUTS                                          │
│                                                           │
│                 当前标签的主要内容                  │
│                                                           │
│  01 / 03                                      切换提示  │
└─────────────────────────────────────────────────────────────┘
```

- 真正全屏：`100vw × 100svh`
- 背景：纯黑 + 很淡的深海蓝径向光，不新增另一套色板
- 主色延续：`#000` / `#031b2e` / `#46d7e8` / `#fff`
- 标题使用现有 Fusion Pixel，感想正文使用现有中文无衬线字体
- 图像边框使用 1px 白/青线，保留当前网站的像素错位阴影
- 页面内部可滚动，打开时禁止全站上下切场

## 4. 音乐页设计

### 4.1 结构：「人」与「作品」分开

不要强迫歌手与专辑使用同一张卡片。音乐页分为两条编辑式轨道：

1. **长期喜欢的歌手**：以歌手名为主，展示「常听作品」。
2. **反复听的专辑**：以方形封面为主，选中后显示专辑名、音乐人、代表单曲和个人感想。

### 4.2 桌面布局

```text

陈绮贞                 张震岳                 卢广仲
吉他手                 跟着感觉走             100种生活
还是会寂寞             这个下午很无聊         励志论
华丽的冒险                                    伤心早餐店

──────────────────────────────────────────

反复听的专辑

[方形封面]  The Dark Side of the Moon
              Pink Floyd
              The Great Gig in the Sky
              「个人感想待补，空时整段不渲染」

[方形封面]  All the Best
              「需确认艺人/版本」
```

### 4.3 交互

- 点击歌手名：该列放大 1.05，青色细线移到当前列；不打开新弹窗
- 点击专辑封面：切换右侧专辑详情
- 专辑封面保持 1:1，歌手图片不是必需项
- 不自动播放音乐，不嵌入 Spotify/Apple Music 第三方播放器
- 如以后需要试听，另行增加合法的外链，不把音频上传到仓库

## 5. 电影页设计

### 5.1 布局

- 使用一条横向海报轨道，与「影像作品」的海报环形成呼应，但不复制环形
- 中间当前海报最大，两侧露出前后海报
- 海报下方显示片名与用户感想，感想最长 80 个中文字
- 没有感想时只显示片名，不显示「待补充」或 AI 生成的假感想
- 不放评分、豆瓣分数、票房或影评标签

### 5.2 影片清单

| 顺序 | 显示名称 | 备注 |
|---|---|---|
| 1 | 《鬼妈妈》 | Coraline |
| 2 | 《垫底辣妹》 | Flying Colors |
| 3 | 《日挂中天》 | 片名按用户输入 |
| 4 | 《珀尔》 | Pearl；用户原文「珀儿」，上线前确认中文名 |
| 5 | 《X》 | 与 Pearl / MaXXXine 使用相邻顺序 |
| 6 | 《玛克辛》 | MaXXXine；用户原文「玛克幸」 |
| 7 | 《罗拉快跑》 | Run Lola Run |

### 5.3 三部影片的关联处理

《X》、《珀尔》、《玛克辛》保留为三张独立海报，但在轨道中连续摆放，底部用一根青色细线表示它们属于同一组。不另外新增大卡片。

## 6. 训练页设计

- 使用用户自己的 3–5 张照片
- 桌面端：一张大图 + 两张较小的训练接触表（contact sheet）布局
- 手机端：单列纵向照片，不做窄屏多列拼贴
- 不放体重、体脂、围度等隐私数据，除非用户明确提供
- 可选信息：训练类型、周频率、一句感受
- 未收到照片前，Luna 只实现结构，不使用网络健身照片或 AI 生成人物代替用户

## 7. 手机端规则

```text
[×]
我的输入源
音乐   电影   训练    <- sticky

当前页内容可上下滚动
横向轨道只负责左右滑动
```

- 子页打开时，网站全局上下切场必须暂停
- 顶部标签导航 sticky，关闭按钮固定右上角
- 音乐歌手：横向文字选择器；当前歌手的作品在下方展开
- 专辑：每张封面占 68–74vw，`scroll-snap-type: x proximity`
- 电影：每张海报占 62–68vw，下方显示当前感想
- 训练：单列图片，宽度约 88vw
- 横向滑动容器设置 `touch-action: pan-x`，子页主容器设置 `touch-action: pan-y`
- 小屏不允许封面或海报遮挡文字、关闭按钮

## 9. 实现结构建议

Luna 可以在 `src/App.jsx` 中先实现，但建议把数据与视图拆分，避免 `App.jsx` 继续膨胀：

```text
src/
├─ data/
│  └─ aestheticInputs.js
├─ components/
│  └─ AestheticDialog.jsx
├─ App.jsx
└─ styles.css
```

`aestheticInputs.js` 中的感想字段允许空字符串，空时不渲染感想容器。

## 10. 交互与无障碍

- 入口使用 `<button>`，不使用伪按钮 `div`
- 子页使用 `role="dialog"` + `aria-modal="true"`
- `Escape` 关闭；关闭后焦点返回「进入我的输入源」
- 页签使用 tablist/tab 语义，支持方向键切换
- 所有封面/海报需有可读 `alt`
- 支持 `prefers-reduced-motion`
- 子页打开时修改全局滚轮/触摸判断，与现有 `evidenceOpen` / `workOpen` 的阻断逻辑一致

## 11. 不要做的事

- 不改主导航，不把「我的输入源」变成第五个主导航
- 不改网站的像素海洋主题
- 不新增彩色渐变、圆角卡片墙、胶囊标签或通用 Bento Grid
- 不为用户编写音乐/电影感想
- 不用 AI 生成的健身人像替代用户照片
- 不移除现有「关于我」经历内容
- 不改动已经稳定的影像作品滑动、镜帧弹窗和联系弹窗

## 12. 验收标准

### 桌面端

- 「关于我」主画面没有新的挡字、重叠或信息过载
- 入口可用鼠标和键盘打开
- 三个页签可切换，选中态清晰
- 音乐页同时看得出「歌手」和「专辑」是两层内容
- 电影海报可点击/滑动切换，三部曲的关联可看懂但不抢眼
- 关闭子页后回到原「关于我」画面

### 手机端

- 子页内纵向滚动不触发全站上下切场
- 音乐专辑与电影海报能正常左右滑动
- 页签和关闭按钮始终可见
- 没有横向页面溢出
- 390 × 844 视口下主要文字可读，封面不挡文字

### 回归检查

- 主页五个场景切换正常
- 运营案例弹窗正常
- 影像作品桌面端可拖动，手机端可横滑
- 作品镜帧详情正常
- 微信二维码弹窗正常
- `npm run build` 通过，控制台无新增 error/warn
